# GitHub Pages ve js.org

Proje iki adres düzenini destekler:

- GitHub Pages: `https://kavtuai.github.io/guildgate-docs/`
- Özel alan adı: `https://guildgate.js.org/`

## GitHub Pages yayını

Depoyu oluşturup `main` dalını gönder:

```bash
git init
git add .
git commit -m "Publish GuildGate documentation"
git branch -M main
git remote add origin https://github.com/Kavtuai/guildgate-docs.git
git push -u origin main
```

GitHub Pages kaynağını **GitHub Actions** olarak seç. `.github/workflows/deploy-pages.yml`, her `main` gönderiminde kontrolleri çalıştırır ve `build` klasörünü yayımlar.

`DOCS_DOMAIN` değişkeni tanımlı değilken Docusaurus şu değerlerle derlenir:

```text
url: https://kavtuai.github.io
baseUrl: /guildgate-docs/
```

## js.org için hazırlık

GitHub Pages ayarındaki özel alan adına şunu yaz:

```text
guildgate.js.org
```

Ardından Actions değişkenini ekle:

```text
DOCS_DOMAIN=jsorg
```

Yeni derlemede değerler şöyledir:

```text
url: https://guildgate.js.org
baseUrl: /
```

GitHub Actions ile yayınlanan sitelerde `CNAME` dosyası işlenmez. Özel alan adı Pages ayarında tutulur.

## js.org başvurusu

`js-org/js.org` deposunu fork et. `cnames_active.js` dosyasına alfabetik konumda şu satırı ekle:

```js
"guildgate": "kavtuai.github.io/guildgate-docs",
```

PR açıklamasında yayımlanmış site adresini ve içeriğin JavaScript geliştiricileriyle ilişkisini doğrudan yaz. Otomatik kontroller geçtikten sonra DNS kaydını js.org yöneticileri açar.

DNS oluşana kadar GitHub Pages alan adı doğrulanmaz ve HTTPS kapalı görünebilir. Bu aşamada Pages ayarını veya `DOCS_DOMAIN` değişkenini tekrar tekrar değiştirme.

## Başvuru kabul edilmezse

`DOCS_DOMAIN` değişkenini kaldırıp Actions çalışmasını yeniden başlat. Site GitHub Pages proje adresinde yayımlanmaya devam eder.
