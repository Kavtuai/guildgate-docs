# Yazı standardı

GuildGate belgesi okuyucuya bir işlemi doğru biçimde tamamlatmalı veya bir davranışın sınırını açıkça anlatmalıdır. Metin, kaynak kod ve yayımlanan paket yüzeyiyle çelişmemelidir.

## Kaynak sırası

Bir iddia yazmadan önce şu sırayı kullan:

1. Yayımlanan TypeScript bildirimi
2. İlgili kaynak uygulaması
3. Test ve contract dosyası
4. Migration veya operating-limits belgesi
5. Release doğrulama kaydı

README örneği ile declaration farklıysa declaration ve çalışan test esas alınır. Belge ile kod arasında uyuşmazlık bulursan önce davranışı doğrula, sonra metni güncelle.

## Cümle yapısı

- Etken fiil kullan: “Origin değerini allowlist ile karşılaştır.”
- Koşulu doğrudan yaz: “Production profilinde HTTP origin reddedilir.”
- Davranışı ölçülebilir biçimde belirt: “Replay en fazla 500 olay döndürür.”
- Bir paragrafta tek ana karar tut.
- Aynı kavram için aynı terimi kullan.
- Gereksiz övgü ve tanıtım cümlesi ekleme.

## Sınırları görünür tut

Örnek, hangi ortamda geçerli olduğunu söylemelidir:

- memory store yalnızca geliştirme ve test için
- load sonucu production kapasite taahhüdü değil
- outbox at-least-once teslimat yapar
- timeout underlying promise'i zorla durdurmaz
- custom store için atomiklik uygulama sorumluluğudur

Başarı koşulunu yazarken hata ve geri dönüş yolunu da belirt.

## Kod örnekleri

- Public import yolu kullan.
- Gerçek API adını ve doğru option yapısını yaz.
- Secret için environment değişkeni kullan.
- `any` veya sahte helper ile güvenlik kararını gizleme.
- Kod çitine uygun dil ve gerekirse dosya başlığı ekle.
- Örneği mümkünse typecheck veya en azından syntax kontrolünden geçir.

```ts title="config.ts"
const gate = createGuildGate({
  app: {
    name: "Dashboard",
    environment: "production",
    baseUrl: "https://dashboard.example.com",
  },
  // ...
});
```

## Türkçe ve İngilizce eşitliği

İki dilde:

- belge kimliği aynı olmalı
- başlık yapısı karşılık gelmeli
- kod örneği aynı davranışı göstermeli
- sürüm, sayı ve limitler eşleşmeli
- bir dilde eklenen güvenlik uyarısı diğerinde de bulunmalı

Kelime kelime çeviri yerine aynı teknik anlamı koru.

## Başlık ve vurgu

Başlıklar okuyucunun aradığı kararı tarif etsin. Çok kısa bir metni fazla alt başlığa bölme. Kalın yazıyı her cümlede kullanma; tabloyu yalnızca karşılaştırma okunabilirliği artırıyorsa ekle.

## Bağlantılar ve referanslar

- Dahili belge bağlantısının build sırasında çözüldüğünü kontrol et.
- Harici bağlantının iddiayı gerçekten desteklediğini açıp doğrula.
- Geçici takip parametrelerini kaldır.
- Var olmayan sayfa, sürüm veya kaynak kimliği üretme.
- Değişebilecek sayısal sonucu tarih ve sürümle birlikte ver.

## Sürüm notu kuralı

Sürüm notu:

- değişen davranışı
- kullanıcı veya adapter etkisini
- gerekli geçiş adımını
- doğrulama sonucunu

ayrı ve kısa maddelerle açıklamalıdır. Dahili çalışma günlüğünü veya başarısız deneme komutlarını yayımlanan sürüm notuna taşıma.

## Kontrol komutları

```bash
npm run search:index
npm run editorial:check
npm run source:check
npm run command:check
npm run site:check
npm run build
```

Bir kontrolü susturmak yerine hatalı dosyayı düzelt. İstisna gerekiyorsa nedeni dar bir dosya ve dar bir işaret için kaynak kodda belgelenmelidir.
