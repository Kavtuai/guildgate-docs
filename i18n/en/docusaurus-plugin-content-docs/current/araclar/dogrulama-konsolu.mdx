# Verification console

This console runs an allowlisted set of documentation commands. It does not start a shell, make network requests, access the file system, or use persistent browser storage.

<CommandPlayground />

## Version commands

```text
version
contracts
exports
```

Expected core information:

```text
Package: @kavtuai/guildgate@1.1.0
Adapter contract: 1.1
Action contract: 1.0
Realtime contract: 1.0
Public export paths: 16
CLI commands: 3
```

## Action checks

```text
action test guild.settings.update
action test guild.settings.update --origin deny
action test guild.settings.update --session missing
action test guild.settings.update --csrf invalid
action test guild.settings.update --permission deny
```

Commands do not connect to a real route or Discord account. They show the control order and stable result for documented scenarios.

## Stores and reliability

```text
store list
store contract
idempotency reservation
transaction finality
deadline settlement
```

For `1.1.0`, review:

- ten store members
- reservation-owner compare-and-set
- atomic session caps
- opaque audit cursors
- bounded outbox claims
- post-commit callback separation
- bounded late settlement

## Realtime

```text
realtime limits
realtime transports
realtime replay
```

WebSocket and Socket.IO share the same inbound control path. SSE is a server-to-client stream with a bounded queue.

## CLI help summary

```text
cli doctor
cli writing-check
cli migration
```

For actual installed-package help, use a terminal:

```bash
npx guildgate-doctor --help
npx guildgate-writing-check --help
npx guildgate-migration --help
```

## Security boundary

Console input is parsed through an allowlist. It does not support:

- arbitrary JavaScript
- `eval` or dynamic functions
- shell or process commands
- HTTP or WebSocket connections
- `localStorage` or `sessionStorage`
- secret or token input

Do not paste real configuration or secrets. The console is only for documentation examples.
